# 登录奖励解锁赠礼：老账号一次性补发

在 `server` 目录运行。只处理已满足登录奖励解锁条件的账号：教程类型 `3`
（MenuSecond）的进度 `>= 20`。默认只读预览，JSON 报告列出玩家 ID 和背包变化：

```sh
go run ./cmd/repair-player-data --db db/game.db > repair-preview.json
```

核对报告后，停止游戏服务器并备份数据库，再执行一次：

```sh
go run ./cmd/repair-player-data --db db/game.db --apply > repair-applied.json
```

也可预先构建：

```sh
go build -o bin/repair-player-data ./cmd/repair-player-data
```

每个符合条件的账号直接收到：

| 物品 | ID | 数量 |
| --- | --- | --- |
| ２Ｂ（破ノ攻機） | 24008 | 1 |
| 戦いの書：破ノ攻機 | 311211 | 40 |
| 覚醒石：破ノ攻機 | 313197 | 5 |
| 三式戦術刀 | 240271 | 1 |
| 天然水晶：軽量 | 312011 | 4 |

服装和武器使用游戏服务相同的发放逻辑，初始化角色、技能和武器记录。
已有同服装时按原有重复服装转换规则处理。当前礼物箱没有武器附带服装的组合
领取类型，因此保持整套直接进背包，不拆成可分别领取的礼物。

所有符合条件账号的背包变化在一个事务中提交，失败整批回滚。工具不创建数据库、
不执行迁移、不改变教程进度，也不写任何领取或修复标记。
**这个命令只执行一次；重复 `--apply` 会再次发放。**
请在部署包含新教程发放逻辑的版本之前，停服执行补发，再启动新版本，避免刚由
新版本发放过奖励的账号被脚本再次补发。

`--master-data` 默认是 `assets/release/20240404193219.bin.e`，应指向目标服务器
实际使用的主数据。工具通过临时副本加载，不修改源主数据。

旧版任务 `3708`～`3711` 修复、真暗ノ天命石扣除、日常签到补偿及
`player_data_repairs` 标记读写逻辑均已移除。

```sh
go test ./cmd/repair-player-data
```
