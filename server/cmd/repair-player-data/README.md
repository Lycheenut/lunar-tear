# 登录解锁与 Companion 赠礼：老账号一次性补发

在 `server` 目录运行。整套赠礼统一要求教程类型 `3`（MenuSecond）的进度
`>= 20`，与新账号的破ノ攻機奖励发放时机一致。无需已经拥有 Companion，
尚未解锁登录奖励的账号不补发。

默认只读预览，JSON 报告列出玩家 ID、背包数量变化及 `CompanionLevels` 等级变化
（新获得的 Companion 的 Before 等级为 0）：

```sh
go run ./cmd/repair-player-data --db db/game.db > repair-preview.json
```

核对报告后，停止游戏服务器并备份数据库，再执行一次：

```sh
go run ./cmd/repair-player-data --db db/game.db --apply > repair-applied.json
```

也可预先构建：

```sh
go build -o bin/repair-player-data ./cmd/repair-player-data
```

工具只加载发奖所需的主数据表，复用服务端的物品发放及重复服装补偿逻辑。
构建和运行均不需要 `server/gen/proto`，无需先生成 protobuf 代码。

符合登录解锁条件的账号直接收到：

| 物品 | ID | 数量 |
| --- | --- | --- |
| ２Ｂ（破ノ攻機） | 24008 | 1 |
| 戦いの書：破ノ攻機 | 311211 | 40 |
| 覚醒石：破ノ攻機 | 313197 | 5 |
| 三式戦術刀 | 240271 | 1 |
| 天然水晶：軽量 | 312011 | 4 |

同一批账号额外直接获得缺失的非主线 Companion：ID `31–53`
共23种，每种1个。`49、50、51` 以50级发放，其余以1级发放（包括53）。
已有 Companion 不重复发放、不转换成重复持有补偿，并保留已有等级；
其中49–51低于50级的会原地提升到50级，保留UUID和获得时间。
持有这些 Companion 不会提前解锁编队槽；客户端仍要求 Companion 教程
（类型8）进度达到10，脚本不改变该教程进度。

服装和武器使用游戏服务相同的发放逻辑，初始化角色、技能和武器记录。
已有同服装时按原有重复服装转换规则处理。当前礼物箱没有武器附带服装的组合
领取类型，因此保持整套直接进背包，不拆成可分别领取的礼物。

所有符合条件账号的背包变化在一个事务中提交，失败整批回滚。工具不创建数据库、
不执行迁移、不改变教程进度，也不写任何领取或修复标记。
**这个命令只执行一次；重复 `--apply` 会再次发放登录解锁赠礼。**
Companion 部分只补缺失和修正49–51等级，重复执行不会重复发放该部分。
请在部署包含新教程发放逻辑的版本之前，停服执行补发，再启动新版本，避免刚由
新版本发放过奖励的账号被脚本再次补发。

`--master-data` 默认是 `assets/release/20240404193219.bin.e`，应指向目标服务器
实际使用的主数据。工具直接只读加载，不修改源主数据或其时间戳。

旧版任务 `3708`～`3711` 修复、真暗ノ天命石扣除、日常签到补偿及
`player_data_repairs` 标记读写逻辑均已移除。

```sh
go test ./cmd/repair-player-data
```
