# 一次性玩家数据修复

在 `server` 目录运行。脚本默认只读预览，输出 JSON 明细；加 `--apply` 才提交。

```sh
go run ./cmd/repair-player-data --db db/game.db > repair-preview.json
```

核对报告后，**停止游戏服务器并备份数据库**，再执行：

```sh
go run ./cmd/repair-player-data --db db/game.db --apply > repair-applied.json
```

也可以预先构建独立可执行文件，在目标服务器运行：

```sh
go build -o bin/repair-player-data ./cmd/repair-player-data
```

`--master-data` 默认是 `assets/release/20240404193219.bin.e`。请使用目标服务器实际运行的主数据文件；可用该参数指定其他路径。数据库必须已完成当前版本的迁移，脚本不会创建数据库或自动迁移。

## 修复规则

1. 任务 `3711` 的状态为完成未领取（`2`）或已领取（`9`）时，从背包材料 `315002`（真暗ノ天命石）扣除 `630`。允许负数；没有材料记录时创建 `-630` 的记录。任务 `3711` 的状态保持不变。
2. 对所有玩家，将任务 `3708`～`3710` 的已领取状态 `9` 改为完成未领取 `2`。保留任务进度、开始及完成时间；未完成、已可领取或没有记录的任务不变。
3. 仅对日常登录奖励 `login_bonus_id=1`，按主数据中的页模板、印章和奖励数量，将领取进度推进至 `user_login.total_login_count`，把缺失区间的奖励直接补进背包（免费宝石进入免费宝石余额）。支持跨页及奖励档位变化；缺少领取记录按 0 天处理。已经领取的天数不会再次补发，也不处理礼物箱中的已有奖励。

补发后的领取时间取玩家最后登录时间与原领取时间中的较大值，避免当日重复领取，也不会让离线玩家丢失下一次登录的奖励。总登录天数不变，其他登录奖励不变。领取进度已超过总登录天数时不回退，并在 `AheadPlayers` 列出内部用户 ID。

三项修复和修复标记在一个 SQLite 事务中提交；任何校验或写入失败均整批回滚。应用时先取得写锁，仍须停服，避免已在处理的游戏请求在修复后写回旧状态。报告列出每位受影响玩家的内部用户 ID、玩家 ID、重置任务、补发天数以及道具的 `Before` / `Delta` / `After`。

成功后在 `player_data_repairs` 保存固定标记 `20260918-missions-3708-3711-login-bonus-1` 及完整报告。同一数据库再次运行只返回 `AlreadyApplied: true`，不会重复扣除、补发或再次重置已重领的任务，也不会处理后来新增的玩家。请勿删除标记后重跑。

当前日常登录奖励支持材料、消耗品和免费宝石。遇到不支持的奖励类型、无效页/印章、超出奖励配置的登录天数、缺失补发所需的最后登录时间或背包整数溢出时会报错，避免少发奖励却推进领取进度。

## 验证

```sh
go test ./cmd/repair-player-data
```

测试使用临时 SQLite 数据库，覆盖只读预览、负余额、跨页和档位变化、缺失领取记录、未完成任务跳过、事务回滚及重复运行。
