# 全体玩家回忆强化重置与金币返还

在 `server` 目录运行。默认只读预览，JSON 报告列出受影响玩家、每件回忆的
原等级、副词条重随机前后的数值，以及金币返还和余额变化：

```sh
go run ./cmd/repair-parts --db db/game.db > repair-parts-preview.json
```

核对报告后，停止游戏服务器并备份数据库，再执行：

```sh
go run ./cmd/repair-parts --db db/game.db --apply > repair-parts-applied.json
```

可先构建再上传到服务器运行：

```sh
go build -o bin/repair-parts ./cmd/repair-parts
```

`--master-data` 默认是 `assets/release/20240404193219.bin.e`，应指向目标服务器
使用的主数据。工具复用 `LoadPartsCatalog`、`LoadGameConfig` 和副词条的
`Initial.Roll()`，无需生成 protobuf 代码。

- 范围：所有玩家当前持有的 `level > 1` 回忆，包括已锁定、已装备及预设中的回忆。
- 回忆及其所有现有副词条的等级恢复为 1。保留副词条数量、槽位、抽选 ID、
  属性类型和计算类型，包括强化时新增的副词条；数值按对应的新初始范围及步长
  等概率重随机。主词条 ID、回忆 ID、锁定状态、获得时间和装备关联保持不变。
- 金币直接加到背包。原等级为 L 时，按该回忆稀有度的费用表，累加强化前等级
  `1, 2, ..., L-1` 的费用，各计一次成功强化。忽略失败次数和成功概率。
  只按现有等级计算，不追溯获得时等级或历史消耗。
- 原本 1 级的回忆及其副词条不处理。只有失败强化而仍为 1 级的回忆也不处理。
- 预览和实际执行分别随机，具体新数值可能不同；实际结果以执行报告为准。
- 整批修复在单个事务中完成，更新回忆及副词条的 `latest_version`。
  缺少费用/回忆定义、副词条定义与已存类型不符、等级异常、金币超过服务端
  int32 范围或写入失败时，整批回滚，不会只重置属性却漏退金币。
- 修复后未再次强化时，重复执行不会再随机或退款。工具不保存一次性执行标记；
  玩家重新强化后再运行，会再次重置并退款，因此应在本次维护中使用。

验证：

```sh
go test ./cmd/repair-parts
```
