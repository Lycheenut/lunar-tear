# 活动共鸣配置

入口：管理页 `/admin/` → 运营活动配置 → `EventQuestChapter` → 活动行的「共鸣配置」。也可以从「关联表配置 → 活动共鸣（服装／武器）」进入。

## 编辑流程

1. 按名称或 ID 选择活动，再选择难度。同名活动保留各自的章节 ID 和日期，不能混为同一批次。
2. 「关卡关联」按难度和加成 ID 分组。修改分组的加成 ID 会改绑该组全部关卡；展开「逐关设置」可只修改一个关卡。`0` 表示无加成。
3. 打开加成定义，通过「查看共鸣服装集合／武器集合」继续查看成员。成员显示名称、实际 ID、突破下限、效果组、期限组；武器各进化形态分别配置。
4. 可以增删成员、打开效果组及其能力／经验／掉落定义，或编辑期限。日期固定为 UTC，支持毫秒；期限组 `0` 不限期，期限结束值 `0` 表示停用。过期条目不会被隐藏。
5. 修改共享集合会影响所有引用关卡。要给单个活动使用独立配置，先「复制集合」到未使用的正整数 ID，再把上游引用改为新 ID。必要时同时复制加成定义并改绑关卡；复制不会自动改动引用。
6. 使用底部「重建并应用」查看成员前后差异和共享影响范围，再确认应用。放弃修改、版本冲突保护、主数据重建和热重载沿用现有流程。

服装使用 `m_quest_bonus_costume_setting_group`，不是旧的 `m_quest_bonus_costume_group`。加成定义中的角色组、旧服装组及支援角色字段在页面中只读，复制时保留原值。

## 保存与校验

保存仍使用现有接口：

- `GET /api/admin/master-data/table?name=m_quest_bonus`：按需返回 `questBonusEditor`，包含章节、实际关卡关联、8 张定义表、服装和武器名称。
- `POST /api/admin/master-data/schedules/preview`：验证候选主数据并返回成员差异、修改前后引用这些组的全部关卡，包括其他活动或非活动关卡。
- `POST /api/admin/master-data/schedules`：按相同请求重建并应用。

请求示意（ID 需替换为当前主数据中有效的值）：

```json
{
  "expectedVersion": "读取时的版本哈希",
  "changes": [
    { "table": "m_quest", "row": 123, "field": "QuestBonusId", "value": "201131" }
  ],
  "questBonusGroups": [
    {
      "table": "m_quest_bonus_costume_setting_group",
      "groupId": 1900000000,
      "rows": [["1900000000", "31029", "0", "1701", "0"]]
    }
  ]
}
```

`row` 是读取结果提供的物理行索引，不是 QuestId；版本哈希用于防止索引过期。`rows` 使用对应表字段顺序，表示**该 ID 的完整成员集合**，其他 ID 的记录保持不变。空数组表示删除该 ID 下的所有成员。新建集合与新引用可以一次提交。

校验包括表白名单、字段类型、组 ID、复合主键去重、突破下限 0～4、时间顺序和新增悬空引用。不能删除仍被引用的集合，不能把同一张定义表的单元格编辑与集合替换混在同一请求。已有的无关悬空引用不会阻止正常编辑；复制一条坏引用属于新增问题，需在同次提交中修复。旧版服装组的历史残留 ID 不参与现代服装集合的引用校验。

新增编辑器本身不会更改活动名单或期限。应用代码更新后，需要重建并重启服务以载入新的内嵌管理页；之后编辑配置可使用现有热重载流程。
