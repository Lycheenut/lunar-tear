# QuestBonus 活动共鸣配置

入口：管理页 `/admin/activities` → `EventQuestChapter` → 活动行「共鸣配置」，或 `/admin/related` →「QuestBonus」。

## 页面与选择器

QuestBonus 沿用关联表的页面布局、统计区、工具栏、正文滚动容器和底部保存栏，无独立侧栏或固定高度。目标活动搜索位于「筛选当前表」，活动起止时间显示在正文活动名称下方。日期跟随顶部「时间基准」选择，可使用本机时间或 UTC。

数据表选择器为普通下拉框，按显示名称排序，仅显示名称，不显示行数及 `m_*` 原始表名。其他大量带标题的选项使用搜索下拉框，支持标题／ID 搜索、键盘选择和虚拟列表。任务奖励及任务期限的搜索框在首次渲染时就可使用，完整选项仍按需加载。

## 编辑流程

1. 在「筛选当前表」搜索目标活动标题或章节 ID，同名复刻活动按各自 ID 分别处理。
2. 在「历史名单来源」选择任意已有加成条目。选项显示加成 ID、服装／武器组 ID，以及各一位代表成员，例如 `200921 · 服装组 200921 (少女の正月 等) / 武器组 200921 (明星の手鞠 等)`。搜索仍覆盖全部加成服装和武器的名称及 ID。完全相同的引用合并展示，输入完整加成 ID 仍可选择具体条目。
3. 选择「替换名单」或「保留当前并补充」。替换模式默认勾选全部来源成员，可取消不需要的成员；补充模式保留左侧全部成员，右侧默认不选，只勾选需要补入的服装／武器。两类成员分别支持全选、清空。切换模式或更换来源会重置来源勾选及规则草稿。
4. 武器规则默认参考本活动。同一武器家族自动匹配，完整规则可一次选择；只覆盖部分关卡阶段的规则也会显示，并标记「部分阶段」。点击该武器旁的「分阶段」，可分别选择各阶段的参考武器，沿用该阶段的突破档位、进化形态及奖章加成。对话框只列出能覆盖来源武器全部形态的本阶段规则，缺失阶段需明确补全后才能保存。重新选择整活动规则会清除该武器的分阶段选择。未勾选的武器不要求配置。历史来源提供所选服装的完整效果，以及所选武器家族的全部已配置进化形态。
5. 「关卡预览」只切换预览阶段。左侧汇总全活动成员，只在其他阶段存在的武器显示「本阶段未配置加成」。武器数量依次显示 0／1／2／3／4 突破的加成，用斜杠分隔。引用配置及实际奖章完全相同的关卡合并展示，保存时仍保留各关卡的原有引用边界。常规、EX Hard 银奖章和金奖章关卡可组合不同规则，不会统一替换成一个历史加成 ID。
6. 活动没有现成武器规则时，选择其他「武器规则参考」活动，并在「关卡／奖章对应」中明确选择各关卡的参考分组和目标活动实际奖章。只选择服装时无需武器规则或对应关系。
7. 核对底部最终、新增及移除数量，再点击「重建并应用」查看保存预览。预览横向对照各阶段的实际奖章和 0～4 突破数量。可准备多个活动，或撤销单个活动、放弃全部草稿。

补充模式按各关卡原有加成组分别合并，保留当前成员的效果、突破档位、进化形态和关卡适用关系。重复服装按 ID、重复武器按实际进化组标记「已包含」，不覆盖当前规则或重复叠加；规则参考仅作用于新增武器。没有勾选新增成员时不产生名单变更，同一请求中的活动时间修改仍正常同步。

例如「記録：想憧の儀」（573）选择来源 201121，以补充模式勾选「少女の祭典」「狩人の祭典」及「道化ノ微笑ミ」「零レル花弁」，为两种新增武器选择所需规则，即可与当前全部成员组成 4 套服装／5 种武器的名单。

「記録：憧憬の路」（511）的来源 200301 有 4 种武器，但其中 3 种仅在常规关卡中有现存规则。编辑器把 30 个相同常规配置合并为一行，与 EX Hard 1、EX Hard 2／3 共展示三个阶段。可以保留这三种武器的常规规则，再明确选择 EX 阶段所需的参考武器；工具不会自动将其改成 WR0a 的较低加成，也不会替用户决定缺失阶段的数值。

共鸣没有独立期限，全部与目标活动起止时间相同，后续修改活动时间时自动同步。按需复制成员组及加成记录，复用现有效果，避免修改其他活动共用的配置。实际共用同一关卡的活动无法使用各自独立期限，保存时会要求先分离关卡引用。

## 保存与校验

- `GET /api/admin/master-data/table?name=m_quest_bonus`：按需返回活动、关卡、加成定义、本地化名称、武器进化关系及实际奖章。
- `POST /api/admin/master-data/schedules/preview`：接收 `questBonusRestores`，生成最终关卡分组、期限及成员效果供核对。
- `POST /api/admin/master-data/schedules`：按同一请求重建并应用。

请求包含 `expectedVersion`、目标活动 ID、历史来源 ID、`mode`（`replace`／`append`）、明确的 `costumeIds` 数组、参考活动 ID、所选武器的 `weapons` 规则，以及跨活动引用时的关卡／奖章对应关系。服装数组可以为空；只有列出的武器家族参与导入。省略 `mode` 的旧请求仍使用完整来源替换，并要求全部来源武器规则。

可选 `weaponPhases` 使用 `{questIds, weapons: [{weaponId, templateWeaponId}]}` 为指定关卡覆盖 `weapons` 中的默认参考武器。覆盖只能作用于已选来源武器，不得重复指定同一关卡的同一家族；最终参考武器必须在该关卡对应的参考加成组中存在，并覆盖来源形态。其他关卡继续使用默认规则。跨活动奖章映射根据组合后实际使用的效果校验。同一原加成组内选择不同武器规则的关卡会分别生成配置。

预览和保存执行同一个生成流程，继续使用版本冲突检查、引用校验、候选主数据验证、备份、原子替换及热重载。

代码更新本身不改变主数据。重建并重启服务后载入新版内嵌管理页，随后可以通过管理页应用配置。
